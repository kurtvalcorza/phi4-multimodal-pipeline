## Adaptation: quantized load, the adapter switch and the fine-tuning sample

- **NF4 load** (`quantization="nf4"`): bitsandbytes 4-bit NF4 with double quantization and fp16 compute on the language model's 128 base projections (`qkv_proj`, `o_proj`, `gate_up_proj`, `down_proj` of 32 layers). `lm_head`, the token embeddings, the vision and audio towers and projectors **and the checkpoint's own LoRA tensors** are excluded (`NF4_SKIP_MODULES`) — bitsandbytes quantises every `nn.Linear` it finds, including peft's `lora_A` / `lora_B` linears, and 4-bit tensors cannot carry gradients. The load needs CUDA; a Tesla T4 holds the model at about 6.8 GB and peaks near 9.2 GB while training.
- **The adapter switch**: upstream `set_lora_adapter` delegates to peft's `set_adapter`, which also sets `requires_grad=True` on every tensor of the chosen adapter, and the model calls it on **every forward** that carries image or audio inputs. Left in place, each training step would re-enable gradients on all 32 layers' vision LoRA, defeating the bounded trainable set. The pipeline replaces `set_lora_adapter` / `unset_lora_adapter` on the loaded instance with functions that only set peft's `_active_adapter` / `_disable_adapters` (mirroring upstream's flags); `adapt` owns `requires_grad` explicitly. This depends on peft 0.13.2 internals, which the pins fix.
- **What is trained**: the vision-LoRA A/B tensors of the last `trained_layers` decoder layers (default 8: 64 tensors, 92,274,688 parameters) as fp32 masters; the adapter is written as fp16 safetensors (about 185 MB) with a manifest that records the base identity and first-shard digest, the five remote-code files, the quantization, the MIT licence, the tensor set, the file digest and the training history.
- **Fine-tuning sample**: VizWiz-Captions (Gurari et al. 2020; CC BY 4.0) from the Hub mirror `mm-eval/VizWiz-Captions` at revision `c4a6d897836e7885d0095134f92d392e4e770539` — `data/val-00004-of-00005.parquet` (392,245,504 bytes, SHA-256 `4492465a…`): the four text columns of all 1,550 rows and the 336 photographs of row group 0, each pinned by size and SHA-256 in `samples.py` (ported from the fleet's `blip-captioning-pipeline`, which pinned this sample first); seeded split 208 / 40 / 70 by image. Nothing is redistributed by this repository.
- **DIMER upload**: on HOLD by decision (2026-09-20). The E2E carrier exists regardless; if the profile is ever uploaded, the served files are the three shards plus the processor/tokenizer files and the five Python files the loader executes (two of which — the vision and speech towers — are large), never an adapter.
