## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/phi4_multimodal_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 26-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition and the remote-code trust boundary (MOD9/MOD10):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (on a fresh runtime all 26: config and tokenizer files, the eight upstream `.py` files, the three SafeTensors shards + index, `README.md`, `LICENSE`, two example clips), from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry — including `configuration_phi4mm.py`, `modeling_phi4mm.py`, `processing_phi4mm.py`, `speech_conformer_encoder.py` and `vision_siglip_navit.py`, which it additionally requires the manifest to list — and only then does `from_pretrained(allow_remote_code=True, weights_dir=WEIGHTS_DIR)` hand the directory to `transformers` with `trust_remote_code=True`. The code that executes is therefore exactly the reviewed revision's; the validator exempts the `trust_remote_code=True` pattern for the carried module cell only and forbids it in every notebook cell. The eight `.py` files and the example clips are git-ignored (never vendored into this repository); the manifest pins their digests.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/phi4_multimodal_input_manifest.json` with one manifest per capability (schema, ceilings `MAX_IMAGES`/`MAX_AUDIOS`/`MAX_NEW_TOKENS`/`MAX_TEMPERATURE`, observed media, request, verdict) and one recorded rejection finding (a five-image request); `evaluation_report` (EVAL21) writes `outputs/phi4_multimodal_evaluation_report.json` with verdict `not-measurable` — the repository ships no metric for open-ended generation (EVAL9), and the report states per capability what labelled data would make it measurable.
- Multi-capability obligations (Notebook Specification §20.8, INF10): each capability has its own section stating its input and output contract; the outputs are generated text with no confidence, and the notebook says so.
- The default image is a synthetic red octagon drawn in code (no download, no caption); the default audio is the checkpoint's own `examples/what_is_the_traffic_sign_in_the_image.wav`, a manifest entry, so the only external access on the primary path is the Hugging Face Hub at the pinned revision. The previous notebook's public stop-sign photograph (a third-party URL) and the LibriSpeech dataset sample were dropped for that reason; `datasets` is no longer used by the tutorial.
- `eager` attention is the portable default; `flash_attention_2` is an explicit opt-in that the tutorial does not use. `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
